## 1. 对比度阈值规则（含替换色值 + 逐个复算）

### 1.1 阈值（WCAG 2.1 AA）

| 内容类型 | 阈值 | 说明 |
| --- | --- | --- |
| **正文 / 小字文本**（< 18.66px 常规 或 < 24px 粗体） | **≥ 4.5 : 1** | 本项目几乎所有文字都落这一档（11–15px） |
| **大号文本**（≥ 24px 或 ≥ 18.66px 粗体） | ≥ 3 : 1 | 本项目只有品牌标题 15px，**不适用**，一律按 4.5 要求 |
| **非文字**（图标、边框、圆点、图形、焦点环） | ≥ 3 : 1 | 如 `.pt-dot`、`.result-item.active` 边框、`.sel-icon` |
| **占位符 / 禁用态** | 不作为例外，同样 ≥ 4.5 | 本项目占位符实测 5.23:1，已达标 |

**判定口径**：一律按**实际渲染色**计算，不按"设计意图色"。半透明浮层（如
`.hint-bar` 的 `rgba(255,255,255,0.82)` 叠在 `--bg` 上）必须**先合成再算**，
等效底色 ≈ `#f5f7f9`。

### 1.2 根因

`--muted` 一个变量被 **6 处复用，底色却各不相同**（白面板 / 浅灰底 / `--accent-soft`）。
背景亮度从高到低：`#ffffff`(1.000) > `#f6f9fc`(0.944) > `--bg #eceff3`(0.860) > `--accent-soft #e6eef5`(0.846)。
**最暗的 `--accent-soft` 是约束瓶颈**——只要 `--muted` 在它上面达标，其余底色自动达标。

> **方向**：调暗 `--muted` 对白底和浅灰底**同时**有利。真正的取舍不是"能不能过"，
> 而是**别调太深**，否则"次要文字"和正文 `--ink` 失去层次。

### 1.3 替换色值（逐个复算）

**① `--muted`：`#6b7785` → `#5c6874`**（一次改动修掉 4 项）

| 用途 | 底色 | 改前 | 改后 | 判定 |
| --- | --- | --- | --- | --- |
| `--muted` on `--accent-soft`（卡片 hover / `.count` 底） | #e6eef5 | **3.89 ❌** | **4.86 ✅** | 瓶颈项 |
| `--muted` on `--bg` | #eceff3 | **3.96 ❌** | **4.94 ✅** | |
| `--muted` on `#f6f9fc`（小地图表头/图例） | #f6f9fc | **4.32 ❌** | **5.39 ✅** | |
| `--muted` on `--panel`（白，`.kv-k` / `.hint` / `.rmeta`） | #ffffff | 4.56 ⚠️ 勉强 | **5.70 ✅** | 顺带拉开余量 |
| 附带：`.hint-bar` 等效底（rgba 白 0.82 叠 bg） | ≈#f5f7f9 | 4.25 ❌ | **5.30 ✅** | |
| 附带：`.selinfo` 底 / 加载态底 | #f7f9fb / #f4f7fa | — | **5.40 / 5.30 ✅** | |

**层次校验**：新 `--muted` 与正文 `--ink #1f2933` 的对比为 **2.59 : 1**——
仍是一个清晰可辨的"次要 vs 主要"层级（旧值 3.23，差距缩小但未消失），符合"别调太深"的取舍。

**取舍备选**（按"改动幅度 ↔ 余量"排序，三选一即可）：

| 候选 | 最差场景（on `--accent-soft`） | 与 `--ink` 层次 | 建议 |
| --- | --- | --- | --- |
| `#5f6b78` | 4.64 | 2.71 | **最小改动**：改动幅度最小、刚过线（余量 0.14，偏紧） |
| `#5c6874` | **4.86** | 2.59 | **推荐**：余量 0.36，抗抗锯齿/四舍五入，层次仍在 |
| `#5a6673` | 5.00 | 2.52 | 高对比取向：更清晰，但"次要感"变弱 |

**② `--highlight` 的"文字/图标"版：新增 `--highlight-ink: #c8401f`**

| 场景 | 底色 | 现值 | 新值 | 判定 |
| --- | --- | --- | --- | --- |
| `--highlight` 作为**文字/图标**（如需要红字、`.sel-icon` 想加强） | #ffffff | **3.64 ❌** | **4.99 ✅** | 同色系更深一档 |
| 同上，落在 `--accent-soft` 上 | #e6eef5 | — | **4.33** ⚠️ | 该组合不出现；如出现改用 `--highlight-ink` 加深 |
| `--highlight` 作**填充/边框/圆点**（现状用法） | #ffffff | 3.64 | 保留 | **非文字，3:1 已达标，不动** |

> 保留 `--highlight` 原值的原因：它是 3D 目标标记与"当前态"边框的颜色，**降暗会削弱场景里的
> 醒目度**；而它当前承担的都是非文字角色，3.64:1 已满足 3:1。文字场景单独用 `--highlight-ink`。

**③ 额外发现（团队复核清单外）：标签文字 `--tag-ink` 不合格**

`.result-item .rtag`（11px 小字，深黄字 `#b06a00` on `#fbf2dd`）实测 **3.84 : 1 ❌**。

| 令牌 | 现值 | 建议值 | on `#fbf2dd` | on 白 |
| --- | --- | --- | --- | --- |
| `--tag-ink` | #b06a00 | **#8f5600** | **5.39 ✅** | 6.00 ✅ |

**④ 已达标、保持不动**（复核确认）：`--ink`/白 14.76、`--accent`/白 5.39、
`--topbar-ink`/`--topbar` 11.74、`--accent-ink`/`--accent-soft` 6.27、
错误态 `#8f3320`/`--highlight-soft` 6.79、顶栏副标题 `#9fb0c0`/`#222e3a` 6.21、
搜索占位符 `#9fb0c0`/`#2c3a48` 5.23。

### 1.4 写进代码的"防回归"约定

- 任何新增文本色，**必须在 §1.3 表格里登记底色与比值**，禁止"看着够黑"就上。
- 同一语义色**只允许一个令牌**；"文字版"与"填充版"若亮度需求不同，拆成 `-ink` 后缀双令牌
  （如 `--highlight` / `--highlight-ink`），不要用一个值硬扛两种用途。

## 2. 间距栅格基准

### 2.1 基准：**4px 主栅格**

所有**结构性间距**（padding / margin / gap / 块间距 / 定位偏移）取 4 的倍数：

`4 · 8 · 12 · 16 · 20 · 24 · 32`

### 2.2 允许的例外（只有三类，且必须成对一致）

| 例外层 | 取值 | 仅允许用在哪 | 理由 |
| --- | --- | --- | --- |
| **微调层** | `2px` | 图标与文字的视觉居中修正、徽标/标签的纵向内边距 | 4px 在这些位置要么太挤要么太松 |
| **微调层** | `6px` | 图标-文字**水平间隙**（`.btn`、`.ph-title`、`.sel-head`、`.demo-flag`） | 图标光学间距的稳定经验值 |
| **微调层** | `10px` | 徽标/标签/胶囊的**水平内边距**（`.count`、`.pt-count`、`.rtag`、`.rzone`、`.demo-flag`） | 小尺寸控件横向呼吸 |
| **内容驱动** | 任意 | 由 JS/config 写入的尺寸：`--joystick-r`、`--drawer-h`、`--panel-w` | 与渲染/手感严格绑定，不纳入栅格 |

**禁止**：把 `3 / 5 / 7 / 9 / 11 / 13 …` 等奇数当间距值。现状的 7/9/11 属历史遗留，
收敛时**就近取到 4 的倍数**（徽标纵向的 3/5 归入微调层 2px 或 4px）。

### 2.3 现状 → 栅格 收敛对照表（可直接改）

| 位置 | 现值 | 收敛为 | 说明 |

### 3.2 层级由「字号 + 字重」共同承担

- 相邻两级**必须**在"字号差 1px"或"字重差 ≥100"里至少占一项，否则会被读成同一级。
  例：T4(12/400) 与 T5(11/700) 靠**字重**拉开；T2(14/600) 与 T3(13/400) 靠**两者**拉开。
- 同一屏内**最多 4 档**同时出现；`.panel-head`(T2) + `.rid`(T3/700) + `.rname`(T2) +
  `.rmeta`(T4) 已接近上限，新增信息请复用现有档位，不要造第 5 档。
- 字重只用 **400 / 500 / 600 / 700** 四档，禁止 800+（会与"克制"调性冲突）。

### 3.3 行高规则

- **标题类**（T1/T2）：`1.15 – 1.35`（紧凑，标题不散）。
- **正文/元数据**（T3/T4/T5）：`1.5 – 1.6`（可读性）。
- **单行按钮 / 徽标 / 胶囊**：不设 `line-height`，靠 `display: inline-flex; align-items: center`
  垂直居中——用 line-height 居中会在换字体时漂移。

## 4. 对齐基准

### 4.1 面板：单一竖向基准线 = **12px**

把面板内所有水平内边距统一为 `12px`，让"面板头文字左沿"与"结果卡边框左沿"
落在**同一条竖线**上：

```
面板左边缘
 │
12px ─┬─ .panel-head 文字左沿        （padding: 12px）
      ├─ .results 容器内边距          （padding: 12px）
      ├─ .result-item 边框左沿        （边框正好压在这条线上）
      └─ .selinfo 文字左沿            （padding: 12px）

24px ──── .result-item 文字左沿       （12 容器 + 12 卡片内边距）
```

**落地**（4 条，全部为"只改数值"）：

```css
.panel-head { padding: 12px; }        /* 原 12px 14px */
.results    { padding: 12px; }        /* 原 10px     */
.result-item{ padding: 12px; }        /* 原 9px 11px */
.selinfo    { padding: 12px; }        /* 原 12px 14px */
```

> 收益：现状里"面板头 14px / 列表 10px / 卡片 11px"三条互不相关的缩进（左沿分别落在
> 14 / 10 / 21px），会让面板看起来"没对齐"。统一后是 **12 / 12 / 24** 一条线，这是
> "像正经产品"最省力的改动之一。

### 4.2 卡片左沿 / 结果卡间距

- 卡片**边框**左沿 = 面板水平基准 `12px`（见上）。
- 卡片之间纵向间距 = `--sp-2 (8px)`（`.result-item { margin-bottom: 8px }`，现值已合规）。
- 卡片**内**的层级缩进只允许两级：编号/名称（24px）、元数据（24px），
  标签/区域徽标跟在名称行尾，不再额外缩进。

### 4.3 按钮基线

- **同一行 / 同一组**按钮高度必须一致；跨组按屏幕档位统一：
  | 场景 | 高度 | 圆角 | 水平内边距 |
  | --- | --- | --- | --- |
  | 顶栏按钮（桌面） | 36px | 7px | 12px |
  | 视图控制按钮（桌面） | 36px | 7px | 12px |
  | 面板收起按钮 | **28px**（原 26px） | 6px | 0（定宽） |
  | 抽屉把手抓取区 | 44px | — | — |
  | **触摸设备一律** | **≥44px** | 7–8px | 16px |
- **按钮内图标**统一 `16px`，图标-文字间隙统一 `--sp-tight (6px)`。
  （现状 `.btn .c-icon` 15px、`.ph-icon` 16px 混用 → 收敛为 16px。）
- 文字垂直居中一律用 `inline-flex + align-items:center`，**不靠** `line-height` 或
  上下 `padding` 凑——保证换字体/换语言不漂。
- 图标尺寸阶梯统一为 **14 / 16 / 18 / 22**：
  | 尺寸 | 用途 | 收敛项 |
  | --- | --- | --- |
  | 22px | 品牌图标 `.brand-icon` | ✅ |
  | 18px | 搜索框内放大镜 `.search-icon`（原 17px → 18px） | 17 → 18 |
  | 16px | 按钮 / 面板头 / 面包屑图标（原 15px → 16px） | 15 → 16 |
  | 14px | 图例 / 提示条 / 小徽标图标（原 13px → 14px） | 13 → 14 |

### 4.4 浮层统一让边

舞台上的浮层（`.breadcrumb` / `.controls` / `.panel-tab` / `.hint-bar` / `.nohit`）

```css
:root {
  --radius-card: 8px;
  --radius-panel: 10px;

  --focus-offset: 2px;
}
/* 统一焦点环：任何可聚焦元素都套这一条，不再各写各的 */
:where(a, button, input, [tabindex]):focus-visible {
  outline: var(--focus-ring);
  outline-offset: var(--focus-offset);
}
/* 深色底例外：--accent 画在顶栏 #222e3a 上只有 1.95:1，等于没画（见下方说明） */
.topbar :where(a, button, input, [tabindex]):focus-visible {
  outline-color: #7fb4dd;
}
```

> **⚠️ 深色底必须换环色（Day 9 落地时才发现，本文件原稿漏了）。**
> `--accent (#2f6f9f)` 在白底上是 5.39:1、在 `--bg` 上是 4.67:1，都够；
> 但**顶栏是深色**（`--topbar #222e3a`），同色环只有 **1.95:1** —— 键盘用户依旧看不见焦点。
> 顶栏内的可聚焦元素（`#search`、`.btn`）改用 `#7fb4dd`（与 `.brand-icon` 同色，保持视觉一致）：
> 在 `#222e3a` 上 **6.23:1**、在搜索框底 `#2c3a48` 上 **5.25:1**。
>
> **推论（写进规则）**：焦点环的约束不是"用哪个颜色"，而是
> **"环色与它所在的那层底色 ≥ 3:1"**。换底色就要重新复算，不能照抄。
> `verify/design-tokens.mjs` 已把这两条都写进断言。

## 6. 移动端不溢出规则

> 收拢 `RUN.md` 既有雏形（触控 ≥44px、搜索框 16px）+ 补全。

### 6.1 既有（保留，来自 RUN.md L113）

- **触控目标 ≥ 44×44px**：按钮、结果卡、面板把手、收起标签。
  视觉尺寸可以更小，但**命中区**必须 ≥44px（用 `::before` 扩热区，如 `.panel-grip` 22px 视觉 / 44px 热区）。
- **搜索框字号 16px**（`#search` @ ≤600px）：避免 iOS Safari 聚焦时自动放大页面。
  同页所有 `<input>` 都适用此规则。

### 6.2 补全：防溢出清单

| 场景 | 规则 |
| --- | --- |
| **横向溢出** | `html, body { overflow: hidden }`（现状已合规）；新增浮层一律 `max-width: calc(100% - 2 * var(--float-gap))`，禁止写死 > 320px 的宽度 |
| **长物资名 / 长路径** | 文本容器 `min-width: 0` + `overflow-wrap: anywhere`；`.kv-v` 已有 `word-break: break-all`，保留 |
| **长面包屑** | `white-space: normal` + `max-width: calc(100% - 20px)`（现状已合规） |
| **flex 行内输入框** | 父级 `min-width: 0`，输入框 `flex: 1 1 auto; min-width: 0`（防被内容顶出容器） |
| **刘海屏安全区** | `viewport-fit=cover` 已声明，但 CSS **尚未消费** `env(safe-area-inset-*)`。补：顶栏 `padding-left/right: max(16px, env(safe-area-inset-left/right))`；底部浮层（摇杆 / 视图按钮 / 收起标签）`bottom: max(12px, env(safe-area-inset-bottom))` |
| **视口高度** | 禁用 `100vh`（地址栏收放会跳）；本项目已用 `position: fixed; inset: 0` + `height: 100%` 规避，**保留**。新代码如需视口高，用 `100dvh` 并配 `100%` 兜底 |
| **图标 + 文字窄屏** | 图标 `flex: none`；文字 `min-width: 0`，必要时 `text-overflow: ellipsis; white-space: nowrap` |
| **字号不随视口缩放** | 一律固定 `px`，不引入 `vw`/`vmin` 字号（`maximum-scale=1.0` 已锁，但 CSS 侧也要自律） |
| **极窄屏（<400px）** | 只留图标、隐藏按钮文字（现状 `.btn span { display: none }` 已合规） |
| **内容不被裁掉** | 面板高度必须**容得下一整张结果卡**（**≈107px**，Day 9 落 12px 内边距后实测；落之前是 101px）；`RUN.md` L796 记录过"高度压过头导致卡片点不到"的真机坑，任何限高改动都要复算 |

## 9. 超出「只改 CSS 数值」范围的问题（**不擅自改，仅列出**）

以下问题**我强烈建议修**，但涉及改 JS 或重构，**超出本次"只改样式数值"的范围**，请团队决策：

1. **`card-canvas.js` 的 `CARD_COLORS` 是 CSS 变量的手工镜像**。
   改了 `--muted` / `--tag-ink` 等值后，若不同步改 `CARD_COLORS`，**3D 场景里的卡片会与右侧面板
   不一致**（正是 `STRUCTURE.md` L63 警告的"改样式只改一处"被破坏）。
   彻底解法：把 `CARD_COLORS` 改成运行时读取——
   `getComputedStyle(document.documentElement).getPropertyValue('--muted')`，
   让 CSS 成为唯一真源。**属于改 JS，本次不做**，但至少落地色值时需**同步改两处**。

2. **顶栏存在一批未令牌化的硬编码色值**（`#2c3a48`、`#3a4856`、`#31414f`、`#9fb0c0`、
   `#ffd28a`、`#3a3018`、`#6b5a2e`、`#46566a` 等）。它们无法被变量统一，也无法在 §1 表格里登记。
   建议抽成 `--topbar-surface` / `--topbar-line` / `--topbar-muted` / `--topbar-warn-*` 令牌。
   **属于令牌重构，本次不做**（但这是"改样式只改一处"的最后一个破口）。

3. **3D 场景内的高亮色由 three.js 材质定义**，与 CSS 令牌分离。若把 `--highlight` 降暗，
   需同步改 3D 材质色，否则"面板当前态"与"场景高亮"会不同色。**本次保留 `--highlight` 原值
   正是为了规避这个问题**（见 §1.3 ②）。
